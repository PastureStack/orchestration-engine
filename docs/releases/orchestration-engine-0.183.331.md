## Root cause and minimal correction

330's imported-container name refresh required an active host mapping even for
stopped instances. The existing stop process synchronously deactivates its
retained mapping to inactive. Actual QA read-only inspection found three stopped
rollback containers with those normal inactive mappings, so their Docker names
were not adopted. The containers and backups were not deleted or manually renamed.

The shared selection and compare-and-swap predicate now allows exactly
`running/active` or `stopped/inactive` instance/mapping pairs. Wrong pairings,
transitional/removed states and every existing Host/Agent/account/full-ID,
unique nonremoved mapping and managed/service/stack exclusion remain fail-closed.
The final update still sets only name and compares every original instance
column. Existing handler CAS-miss behavior remains no notification and no retry.
No authentication, schema, migration, Agent/plugin or state lifecycle change.
