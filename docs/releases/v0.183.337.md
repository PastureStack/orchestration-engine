# Engine v0.183.337

## API Key audit identity

Failed Key edits could be recorded with a numeric internal ID after request
validation, while earlier rejections and successful edits used the public Key ID.
This made per-Key queries omit the later failures. Governance audit now formats
the authoritative request/response identity consistently. It never reads the
target Key or owner from an untrusted request body.

This change does not alter policy decisions, MFA confirmation, Key persistence,
or audit ownership. HTTP acceptance and actual operation completion remain
separate. Previously stored events are not rewritten; the matching Server reader
provides compatibility for historical numeric Key IDs within existing RBAC.

## Validation

Focused tests cover both Key types, public/internal request IDs, failed status
400/401/403/409/500, exactly-once completion, server response identity, and secret
exclusion. Existing audit and MFA confirmation tests remain required. Component
tests do not by themselves establish full platform or browser acceptance.
